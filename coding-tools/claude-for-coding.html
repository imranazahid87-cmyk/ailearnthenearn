Lesson 01 — Foundations

Coding with Claude, from first principles

A short, practical course on using Claude as a coding partner — not as a magic autocomplete, but as a collaborator you can reason with, question, and correct.

01.1 What Claude actually is for a developer

Claude is a large language model that can read, write, explain, and refactor code across most popular languages. Unlike a simple autocomplete tool, it can hold a conversation about why a piece of code should exist a certain way — trade-offs, edge cases, and design intent — not just what to type next.

You can reach it through the Claude.ai chat interface, the Claude API for building your own tools, or Claude Code, an agentic command-line assistant that can read a repository, plan a change, and edit multiple files on your behalf.

01.2 Where it fits in your workflow

Explaining unfamiliar code

Paste a function or a whole file and ask it to walk you through the logic before you touch it.

Drafting from a spec

Describe the behaviour you want and get a first implementation to react to and refine.

Debugging with context

Share an error and the relevant code; it reasons about the likely cause instead of guessing blindly.

Reviewing before you ship

Ask it to critique a diff for readability, naming, and edge cases you may have missed.

01.3 The one mindset shift that matters

Treat it like a sharp colleague, not an oracle. Give it real context — the file, the error, the constraint you're under — and it gives you real, checkable reasoning back. Vague prompts get vague code.

That's the whole foundation. Once you internalise "context in, reasoning out," the rest is just practice — which is exactly what Lesson 2 covers.

Lesson 02 — Practice

A working routine for daily coding

Concrete steps and habits for getting reliable, high-quality output — plus a few mistakes worth avoiding.

02.1 A five-step routine

  1. 01 State the goal in one sentence before anything else — what should be true when you're done.
  2. 02 Paste the exact file or function, not a paraphrase of it — accuracy of context drives accuracy of output.
  3. 03 Ask for a plan first on anything non-trivial, and approve or amend it before code is written.
  4. 04 Run the code yourself; never assume a snippet works without testing it in your environment.
  5. 05 Ask it to explain any line you don't understand — an unexplained line is a bug waiting to happen.

02.2 A small example

A typical prompt that gives Claude enough to work with:

I have a Python function that dedupes a list of dicts by "id"
but keeps crashing on missing keys. Here's the function and the
traceback. Explain the bug, then fix it, then show me a test.

Notice the shape: context (what the function does), symptom (the traceback), and explicit ask (explain, fix, test). That shape works for almost any request.

02.3 Mistakes to avoid

Copy-pasting blind

Read every suggested change before it goes into your codebase — you own the code, not the model.

One giant prompt

Break large features into smaller, reviewable steps instead of asking for an entire system at once.

No test asked for

Always ask for a test alongside a fix — it's the fastest way to confirm the reasoning was right.

Losing the "why"

If a suggestion feels wrong, ask it to justify the choice before accepting or rejecting it.

The developers who get the most out of Claude aren't the ones who prompt the most — they're the ones who review the closest.

Lesson 01 — Foundations

Windsurf, the agentic IDE

Windsurf is a standalone AI-native code editor built around "Cascade," an agent that can understand an entire codebase and carry out multi-step coding tasks with the developer staying in the loop.

01.1 What makes Windsurf different

Windsurf's core idea is "flow" — keeping the agent working alongside you continuously, aware of what you're editing, rather than only responding to isolated prompts. Cascade can trace dependencies across files, run terminal commands, and take multi-step actions toward a goal, checking in with you at meaningful decision points instead of after every keystroke.

It positions itself as a full editor replacement, similar in spirit to Cursor, but with its own take on how much autonomy the agent should have by default.

01.2 Where it fits in your workflow

Multi-step feature work

Hand off a feature that spans several files and let the agent plan and execute the sequence.

Codebase-aware chat

Ask questions that require understanding relationships across many files at once.

Terminal-integrated tasks

Let the agent run builds, tests, or scripts as part of completing a task, not just editing text.

Daily-driver editing

Works as your primary editor, with the agent present throughout rather than summoned occasionally.

01.3 The one mindset shift that matters

Stay at the checkpoints. Windsurf is designed for you to review at decision points, not to walk away entirely — the more autonomy you grant, the more deliberately you should check in at each step.

Lesson 02 — Practice

A working checkpoint routine

How to let Cascade carry real work forward without losing visibility into what it's doing.

02.1 A five-step routine

  1. 01 State the end goal and any hard constraints up front — performance limits, style rules, files to avoid.
  2. 02 Ask for a plan before execution on anything multi-step, and adjust it before work begins.
  3. 03 Review each checkpoint as it's presented rather than batching approvals at the end.
  4. 04 Let it run tests or builds itself, but read the actual output rather than trusting a summary.
  5. 05 Commit at natural milestones so a misstep is easy to isolate and roll back.

02.2 A small example

A prompt that gives Cascade a clear, checkable multi-step task:

Add rate limiting to all public API routes: 100 requests
per minute per IP, return 429 on limit, and log violations.
Plan the approach first, then implement and add tests.

Asking for a plan before implementation gives you a natural checkpoint to catch a misunderstanding before any code is written.

02.3 Mistakes to avoid

Granting too much autonomy early

Start with tighter checkpoints and loosen them once you trust its judgement on your codebase.

Skipping the plan step

Jumping straight to execution on complex tasks makes misunderstandings expensive to unwind.

Not reading terminal output

A task marked "done" can still have failed silently if you don't check the actual logs.

No commit discipline

Long uncommitted agent sessions make it hard to know exactly what changed and why.

Windsurf works best as a genuine collaborator — the value comes from staying engaged at each checkpoint, not from disengaging entirely.

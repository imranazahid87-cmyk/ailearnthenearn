Lesson 01 — Foundations

Bolt.ai, from idea to running app

Bolt.ai is a browser-based AI app builder: describe what you want, and it scaffolds, writes, and runs a full-stack project in front of you — no local setup required.

01.1 What makes Bolt different

Most AI coding tools assist inside an editor you already have open. Bolt instead gives you the whole environment: a prompt box, a live file tree, and an in-browser terminal, all connected to a real running project via WebContainers technology. You watch the app boot up as it's generated.

That makes it especially strong for starting something new — a landing page, a prototype, a small tool — rather than for deep work inside a large, established codebase.

01.2 Where it fits in your workflow

Rapid prototyping

Turn a rough idea into a clickable, working prototype in minutes, without setting up tooling first.

Landing pages & MVPs

Describe layout and copy, get a deployable front end you can iterate on immediately.

Learning by watching

Beginners can see a project's file structure built step by step, in real time.

Client demos

Spin up a shareable, working preview during a conversation instead of promising one later.

01.3 The one mindset shift that matters

Think in "versions of the app," not "lines of code." Bolt works best when you describe outcomes — what a screen should do — and then course-correct with follow-up prompts, rather than trying to hand-edit its output line by line.

That's the foundation. Lesson 2 walks through an actual build routine.

Lesson 02 — Practice

A working build routine

A repeatable process for going from a blank prompt to something you'd actually ship, plus pitfalls to avoid.

02.1 A five-step routine

  1. 01 Describe the whole app in one paragraph first — purpose, main screens, and who it's for.
  2. 02 Let the first generation finish fully before asking for changes; interrupting mid-build causes broken state.
  3. 03 Review the live preview like a user would, then request one focused change at a time.
  4. 04 Use the built-in terminal to check for errors directly, instead of guessing from the preview alone.
  5. 05 Once it's stable, export or connect to GitHub so the project lives outside the browser session too.

02.2 A small example

A prompt that gives Bolt enough to scaffold something useful on the first try:

Build a simple recipe-sharing site: a home page listing
recipes as cards, a detail page per recipe, and a form to
add a new one. Use a clean, warm design with a card layout.

Notice it states the pages, the core interaction (adding a recipe), and a design direction — enough structure without over-specifying implementation details.

02.3 Mistakes to avoid

Vague one-liners

"Build me an app" with no detail forces Bolt to guess at scope, layout, and purpose.

Too many asks at once

Bundling five changes into one prompt makes it harder to tell what actually broke, if something does.

Skipping the preview

Always click through the running app before requesting the next change — don't assume it matches the prompt.

No backup of your work

Export or push to a repo regularly; treat the browser session as a workspace, not permanent storage.

Bolt is fastest when you treat it like pairing with someone who builds quickly but needs clear direction — the clearer the brief, the less cleanup afterward.
